# Статика: балки и рамы

Составление, решение и проверка уравнений равновесия плоской рамы с пошаговым решением
в стиле решебника. Перенос прототипа `prototype/statika.html` на TypeScript + Vite + React.

Прототип — источник истины по поведению и ответам; в репозитории он не меняется.

## Команды

```bash
npm install
npm run dev        # приложение (http://localhost:5173)
npm test           # все тесты (Vitest)
npm run typecheck  # проверка типов
npm run build      # сборка в dist/
npm run golden     # переснять эталоны с прототипа (нужен Chromium, см. ниже)
npm run build && npm run compare:ui   # сравнить интерфейс с прототипом в браузере
npm run build && npm run e2e:files    # сохранение, открытие и отчёт в PDF в браузере
```

## Устройство

Приложение состоит из разделов (модулей), каждый — отдельная вкладка со своим состоянием, историей отмены
и данными в файле проекта. Готовы разделы «Балки и рамы», «Изгиб: эпюры Q и M» и «Подбор сечения»; остальные вкладки видны
по дорожной карте, но пока недоступны.

| Папка | Что внутри |
|---|---|
| `src/app/` | оболочка: вкладки (`Shell.tsx`), описание раздела (`module.ts`), список разделов (`registry.ts`), кнопки файлов (`FileBar.tsx`); клавиши Ctrl+S/O/Z/Y и перетаскивание файла |
| `src/shared/` | общее для всех разделов: текст решения как структура (`doc.ts`), числа и углы (`format.ts`), многочлены (`poly.ts`), Гаусс и ранг, идентификаторы, история отмены (`history.ts`), конверт файла проекта (`projectFile.ts`), правила и обозначения (`conventions.ts`), `DocView`, `Notice`, стили |
| `src/modules/frames/` | раздел «Балки и рамы» (ниже) |
| `src/modules/bending/` | раздел «Изгиб»: эпюры Q и M по схеме и реакциям «Балок и рам» (см. «Эпюры Q и M») |
| `src/modules/sections/` | раздел «Подбор сечения»: прямоугольник, круг, двутавр по M и Q с эпюр (см. «Подбор сечения») |

Раздел «Балки и рамы» (`src/modules/frames/`); ядро — чистые модули без DOM:

| Папка | Что внутри |
|---|---|
| `model/` | типы (`types.ts`), геометрия (`geometry.ts`: обход дерева, координаты, `geomOK`, части по шарнирам, распределённая нагрузка), правка конструкции (`edit.ts`), готовые задачи (`presets.ts`), задачи Мещерского (`textbook.ts`), файл проекта (`project.ts`) |
| `solver/` | расчётная модель и уравнения-кандидаты (`model.ts`, `equations.ts`), решение (`solve.ts`), проверка (`check.ts`) |

### Как добавить раздел

1. Папка `src/modules/<имя>/` со своими `model/`, `solver/`, `text/`, `draw/`, `ui/` — общие части брать из `src/shared/`.
2. `index.tsx` возвращает `StatikaModule` (`src/app/module.ts`): идентификатор (он же поле `module` в файле),
   подпись вкладки, хранилище (отмена, повтор, сохранение и открытие файла, уведомления) и экран.
3. Добавить раздел в `createModules()` и убрать его из `PLANNED` в `src/app/registry.ts`.
4. Эталоны из задачника — в тесты раздела; браузерные проверки — в `scripts/`.

### Пояснения к ходу решения

`analyze(s, { explain: true })` добавляет к решению абзацы-пояснения (класс `explain`):
какие реакции даёт каждая опора, правило знаков моментов и теорема Вариньона,
как заменяется распределённая нагрузка, почему система определима, **почему в выбранном уравнении
осталось одно неизвестное** (линия действия проходит через точку, сила перпендикулярна оси,
пара не входит в проекции, значение уже найдено), как выбрано проверочное уравнение, что значит знак «−».

Без `explain` текст совпадает с прототипом (кроме исправленных случаев ниже); `explain` только добавляет абзацы — это проверяется тестом.

## Обозначения углов и разбор плеч

- У силы, опорного стержня и наклонного катка можно выбрать обозначение угла (α, β, γ, φ, ψ, θ); значение
  по-прежнему вводится числом. В уравнениях угол пишется буквой (F·sin α·2, для угла больше 90° — sin(180° − α)),
  в подстановке — числа, в первом шаге решения — «Углы: α = 60°». Без обозначения всё как раньше.
- В режиме пояснений под каждым уравнением моментов — разбор слагаемых: какая составляющая силы, где приложена
  (для равнодействующей — в центре тяжести эпюры), почему плечо именно такое (расстояние по горизонтали или
  по вертикали от точки моментов) и откуда знак.

## Составные конструкции (внутренние шарниры)

Шарнир — свойство точки (конфигуратор → «Внутренние шарниры»; доступен в точках, где сходятся хотя бы два участка).

- Шарниры делят раму на жёсткие части (`partsOf` в `src/modules/frames/model/geometry.ts`), части нумеруются I, II, … по обходу.
- В шарнире на вторую часть действуют взаимные силы X, Y, на первую — такие же в обратную сторону
  (в книге — «±»). Опоры и нагрузки, приложенные в самом шарнире, относятся к первой части.
- Распределённая нагрузка, проходящая через шарнир, делится на куски — у каждого своя равнодействующая.
- Уравнения: по три на каждую часть (моменты — прежде всего относительно опор и шарниров части) и уравнения
  для всей конструкции, где внутренние силы взаимно уничтожаются. Определимость — по рангу против 3·(число частей).
- В решении появляется шаг «Расчленяем конструкцию по шарнирам», уравнения помечены номером части (ΣM_D^II),
  в пояснениях — почему силы другой части или внутренние силы не входят в уравнение.
- Без шарниров расчёт и текст прежние (проверяется всеми эталонами прототипа).

Эталоны — Мещерский 3.37, 4.32, 4.33, 4.34, 4.37, 4.38 (`TEXTBOOK_COMPOSITE`, `tests/composite.test.ts`);
для них и для 5000 случайных составных конструкций независимо проверяется равновесие каждой части.
Готовые задачи: «Составная балка с шарниром» (4.32), «Трёхшарнирная рама (арка)» (4.34).

## Эпюры Q и M (вкладка «Изгиб»)

Своей схемы у раздела нет: он берёт конструкцию и найденные реакции из «Балок и рам» (отмена, файлы и название — общие;
«Изменить схему» переводит на ту вкладку). Готовые задачи: пример Антонова (рис. 8.5), задача 2 Антонова (схема 7),
консоль, а также балки из «Балок и рам».

- **Расчёт** (`bending/model/forces.ts`) — метод сечений для любой конструкции-дерева: у участка есть начало P0 и орт u,
  вклад каждой нагрузки своей части в N, Q, M — многочлен от координаты сечения (сила, пара, распределённая нагрузка
  за участком — точными равнодействующими, на участке — интегралом). Для балки u направлен слева направо; для рам
  с вертикальными участками понадобится только выбрать участки и их «свою» часть — формулы те же.
- **Балка** (`bending/model/beam.ts`): участки между концами, опорами, точками сил и пар, концами распределённой нагрузки
  и шарнирами; на каждом — Q(z), M(z), экстремумы M (где Q = 0).
- **Решение** (`bending/text/solution.ts`): реакции, правило знаков, участки, формулы Q(z) и M(z) в буквах и числах,
  значения на концах и в экстремуме, проверки скачков (Q — на силу, M — на пару; M = 0 на концах и в шарнирах),
  ответ — наибольшие |Q| и |M| и опасное сечение.
- **Чертёж** (`bending/draw/diagrams.ts`): эпюры под расчётной схемой в том же масштабе, со штриховкой, знаками и значениями.
- **Правила и обозначения** (`src/shared/conventions.ts`, панель во вкладке, запоминаются в браузере): сторона эпюры M —
  сжатые волокна (машиностроение, Антонов; по умолчанию) или растянутые (строительная механика); ось вдоль балки z или x;
  обозначения Q, M или Q_y, M_x. Знаки Q и M — как почти во всех учебниках: Q «+», если слева сила вверх;
  M «+» при изгибе выпуклостью вниз.
- **Проверка** (`tests/bending.test.ts`): эталон Антонова (Q = ⅔ql и −4/3·ql, M_max = 8/9·ql²); для готовых задач
  и 3000 случайных балок (в том числе составных) Q и M по левой части совпадают с независимым расчётом по правой части
  (`tests/helpers/cut.ts`: свои направления сил, интегрирование нагрузки по Симпсону), скачки равны силам и парам,
  M = 0 на свободных концах и в шарнирах. Проверено, что порча формулы нагрузки ловится.

## Подбор сечения

Задача 2 Антонова целиком: по наибольшим |M| и |Q| (с эпюр вкладки «Изгиб» или заданным вручную) подобрать
прямоугольник h = k·b, круг и двутавр, выбрать самое лёгкое сечение и проверить все три по касательным напряжениям.

- **Расчёт** (`sections/model/design.ts`): W ≥ M/[σ]; прямоугольник b ≥ ∛(6W/k²), круг d ≥ ∛(32W/π) — размеры округляются
  вверх до 1 мм; двутавр — наименьший номер с σ = M/Wx ≤ [σ] (можно разрешить перенапряжение, %). Касательные:
  прямоугольник 3/2·Q/A, круг 4/3·Q/A, двутавр Q·Sx/(Ix·s). Единицы — кН, кН·м, МПа, см; переводы показаны в решении.
- **Сортамент** (`sections/model/sortament.ts`): двутавры ГОСТ 8239-89 №10–60. Тест проверяет согласованность каждой строки:
  Wx = 2Ix/h, Wy = 2Iy/b, радиусы инерции, масса = 0,785·A, площадь по размерам с учётом скруглений, Sx ≈ 0,57·Wx.
- **Исходные данные**: [σ] прямо или через σт/n, [τ], отношение h/b, перенапряжение; готовые данные — задача 2 Антонова
  (группа 10) и типовая сталь. Файл проекта раздела (`module: "sections"`) хранит схему и исходные данные.
- **Решение**: исходные данные, требуемый W, три сечения, сравнение по расходу материала, проверка по касательным,
  ответ; эскизы сечений в одном масштабе. Эталон — задача 2, схема 7, группа 10, посчитанная вручную:
  W = 678,26 см³, 101×202 мм, ⌀191 мм, двутавр №36, τ = 16,86 МПа (`tests/sections.test.ts`).

## Проекты и отчёт

- **Сохранить** (Ctrl+S) — файл `<название> <дата>.statika.json`: раздел, конструкция, элементы, «Что найти», название.
- **Открыть** (Ctrl+O) или перетащить файл на страницу. Файл полностью проверяется: ссылки на точки,
  допустимые значения, связность и непересечение участков; ошибки — понятным текстом, схема при ошибке
  не меняется. Открытие отменяется, как любое действие. Файл открывается в своём разделе — вкладка переключается сама.
- **Решение в PDF** (или Ctrl+P) — отчёт на A4: «Дано», чертёж в двух видах, «Найти», пошаговое решение
  (с пояснениями, если они включены), ответ. Файл сохраняется через «Печать → Сохранить как PDF»:
  текст и чертежи остаются векторными, кириллица и формулы — как на экране.

Формат файла — версия 2: общий конверт `src/shared/projectFile.ts` (`format`, `version`, `module`, `title`, `savedAt`)
и данные раздела рядом с ним (для «Балок и рам» — `src/modules/frames/model/project.ts`). Файлы версии 1 (без `module`)
открываются в разделе «Балки и рамы».

## Как проверяется правильность

1. **Эталонные ответы** (`tests/reference.test.ts`): все готовые задачи с точностью 1e-3.
2. **Сверка с прототипом** (`tests/golden.test.ts`, `tests/edit.test.ts`); в случаях, где поведение
   намеренно изменено (см. «Отличия от прототипа»), сверяется всё, кроме затронутого. `scripts/capture-golden.ts` открывает
   копию прототипа в Chromium (в копию добавлена одна строка, открывающая внутренние функции), прогоняет
   готовые задачи и 600 случайных конструкций и сохраняет в `tests/golden/`: HTML решения, статус, значения,
   порядок уравнений, коэффициенты всех уравнений-кандидатов, заголовки карточек, поправки состояния,
   результат «разделить/убрать участок». Порт должен совпасть по всем пунктам: текст — посимвольно,
   числа — с допуском 1e-12 (Chromium и Node по-разному считают `Math.sin` в последнем бите).
3. **Свойства на случайных конструкциях** (`tests/property.test.ts`, fast-check): для каждой определимой системы
   найденные реакции уравновешивают тело. Проверка **независимая**: свои координаты, свои направления опор,
   распределённая нагрузка интегрируется по Симпсону, а не заменяется формулой центра тяжести.
   Правки геометрии не ломают конструкцию. Тест проверен на чувствительность: порча формулы центра тяжести
   трапеции или знака момента ловится сразу.
4. **Чертёж** (`tests/drawing.test.ts`): SVG обоих видов совпадает с прототипом для готовых задач и 600 случайных конструкций.
5. **Интерфейс в браузере** (`scripts/compare-ui.ts`): 84 одинаковых действия в прототипе и в приложении —
   все готовые задачи, правка участков и элементов, перетаскивание, правка размера на чертеже, двойной щелчок,
   отмена и повтор (кнопками и клавишами), мастер. После каждого шага сравниваются чертёж, решение, поля,
   выделение, сообщения, кнопки истории и мастер.
6. **История и состояние** (`tests/store.test.ts`, `tests/history.test.ts`); файл проекта (`tests/project.test.ts`) и браузерная проверка
   сохранения, открытия, перетаскивания, ошибок, вкладок, файлов версии 1 и чужих разделов, PDF (`scripts/e2e-files.ts`).
7. **Известные особенности прототипа** (`tests/known-bugs.test.ts`) — зафиксированы как есть, см. ниже.

Путь к Chromium для `npm run golden`: переменная `CHROMIUM_PATH`, иначе ищется в `/opt/pw-browsers`.

## Отличия от прототипа

Исправлены ошибки, влиявшие на расчёт (`tests/fixes.test.ts`):

1. **Определимость — по рангу.** Раньше при n > 3 статус «неопределима» ставился до проверки ранга.
   Теперь: ранг 3 и n > 3 — неопределима, степень n − 3; ранг < 3 — геометрически изменяема
   (например, четыре вертикальных катка).
2. **Знакопеременная распределённая нагрузка** (q₁ и q₂ разных знаков) заменяется двумя силами Q′ и Q″ —
   по одной на каждый треугольник эпюры по обе стороны от нуля. Раньше была одна сила: при q₁ = −q₂
   она равна нулю, и пара сил терялась; в остальных случаях точка приложения уходила за участок.
   На расчётной схеме рисуются обе силы.

Исправлена ошибка этапа 4: при **открытии файла** терялись внутренние шарниры (составная конструкция
считалась как сплошная). Проверяется в `tests/store.test.ts` и в браузере.

Исправлена ошибка редактора: **«Убрать участок»** теперь работает (баг №7: `geomOK` проверялся,
пока удаляемый узел ещё был в списке узлов, и проверка проваливалась всегда).

В режиме пояснений добавлено: проекции каждой наклонной силы через угол с той осью, от которой пользователь
отсчитывал угол (угол больше 90° приводится к острому), и простое объяснение, что значит «по нормали».

## Особенности прототипа, не влияющие на расчёт

Перенесены без изменений (`tests/known-bugs.test.ts`):

3. «Что найти» хранится по имени (`R_E`); после добавления точки имена сдвигаются и отметка теряется
   или переходит на другую реакцию.
4. Проверочное уравнение не может показать «Ошибка»: решение с невязкой отсеивается раньше как «равновесие невозможно».
5. В записи уравнений при α > 90° стоит острый угол с осью (например, `cos 60°` для 120°); числа верные,
   в пояснениях переход показан явно.
6. Соглашение: у опорного стержня «+» направлен от опоры к конструкции, то есть «+» — сжатие.

2. ✅ Подбор сечения (прямоугольник, круг, двутавр по сортаменту), проверка по касательным напряжениям.
3. Сходящиеся силы — узел, в котором сходятся стержни и тросы (Мещерский §2).
4. Наклонные балки и рамы — участки под любым углом.
5. Фермы — вырезание узлов и сечения Риттера.
6. Трение — предельное равновесие, интервалы ответа.
7. Центр тяжести — составные фигуры (Мещерский §9).
8. Пространственные системы сил (Мещерский §6–8).
9. Эпюры N, Q, M для рам; геометрические характеристики составных сечений; растяжение-сжатие; кручение.

## Отложено (решения от 2026-09-24)

- **Наклонные балки и стержни** — отдельным модулем геометрии, когда понадобятся; решатель, текст и отчёт общие.
- **Отчёт** — остаётся через печать браузера («Сохранить как PDF»); прямое скачивание PDF не делаем.
- **Особенности прототипа №3 и №4** (отметка «что найти» после новой точки; проверка не показывает «Ошибка») —
  на расчёт не влияют, пока не исправляем (`tests/known-bugs.test.ts`).
