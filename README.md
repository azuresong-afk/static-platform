# Статика: балки и рамы

Составление, решение и проверка уравнений равновесия плоской рамы с пошаговым решением
в стиле решебника. Перенос прототипа `prototype/statika.html` на TypeScript + Vite + React.

Прототип — источник истины по поведению и ответам; в репозитории он не меняется.

## Команды

```bash
npm install
npm run dev        # страница для просмотра решения (http://localhost:5173)
npm test           # все тесты (Vitest)
npm run typecheck  # проверка типов
npm run build      # сборка в dist/
npm run golden     # переснять эталоны с прототипа (нужен Chromium, см. ниже)
```

## Устройство

Ядро — чистые модули без DOM:

| Папка | Что внутри |
|---|---|
| `src/model/` | типы (`types.ts`), геометрия (`geometry.ts`: обход дерева, координаты, `geomOK`, распределённая нагрузка), правка конструкции (`edit.ts`), готовые задачи (`presets.ts`), форматирование чисел (`format.ts`) |
| `src/solver/` | расчётная модель и уравнения-кандидаты (`model.ts`, `equations.ts`), ранг (`rank.ts`), Гаусс (`gauss.ts`), решение (`solve.ts`), проверка (`check.ts`) |
| `src/text/` | пошаговое решение как структура (`solution.ts` → `doc.ts`), HTML в разметке прототипа, подписи и статусы (`labels.ts`) |
| `src/core.ts` | `analyze(structure, { notTarget, explain })` → модель, решение, структура текста, HTML |
| `src/ui/` | временная страница этапа 1: выбор задачи, «Что найти», решение с пояснениями |

### Пояснения к ходу решения

`analyze(s, { explain: true })` добавляет к решению абзацы-пояснения (класс `explain`):
какие реакции даёт каждая опора, правило знаков моментов и теорема Вариньона,
как заменяется распределённая нагрузка, почему система определима, **почему в выбранном уравнении
осталось одно неизвестное** (линия действия проходит через точку, сила перпендикулярна оси,
пара не входит в проекции, значение уже найдено), как выбрано проверочное уравнение, что значит знак «−».

Без `explain` текст совпадает с прототипом; с `explain` меняются только добавленные абзацы — это проверяется тестом.

## Как проверяется правильность

1. **Эталонные ответы** (`tests/reference.test.ts`): все готовые задачи с точностью 1e-3.
2. **Сверка с прототипом** (`tests/golden.test.ts`, `tests/edit.test.ts`). `scripts/capture-golden.ts` открывает
   копию прототипа в Chromium (в копию добавлена одна строка, открывающая внутренние функции), прогоняет
   готовые задачи и 600 случайных конструкций и сохраняет в `tests/golden/`: HTML решения, статус, значения,
   порядок уравнений, коэффициенты всех уравнений-кандидатов, заголовки карточек, поправки состояния,
   результат «разделить/убрать участок». Порт должен совпасть по всем пунктам: текст — посимвольно,
   числа — с допуском 1e-12 (Chromium и Node по-разному считают `Math.sin` в последнем бите).
3. **Свойства на случайных конструкциях** (`tests/property.test.ts`, fast-check): для каждой определимой системы
   найденные реакции уравновешивают тело. Проверка **независимая**: свои координаты, свои направления опор,
   распределённая нагрузка интегрируется по Симпсону, а не заменяется формулой центра тяжести.
   Правки геометрии не ломают конструкцию. Тест проверен на чувствительность: порча формулы центра тяжести
   трапеции или знака момента ловится сразу.
4. **Известные особенности прототипа** (`tests/known-bugs.test.ts`) — зафиксированы как есть, см. ниже.

Путь к Chromium для `npm run golden`: переменная `CHROMIUM_PATH`, иначе ищется в `/opt/pw-browsers`.

## Особенности прототипа, похожие на ошибки

Перенесены без изменений; исправляются только после согласования.

1. Статус «неопределима» ставится при n > 3 до сравнения с рангом; степень считается как n − 3.
   Четыре вертикальных катка: ранг 2 (горизонталь свободна), но статус — «неопределима, степень 1».
2. Трапеция с q₁ = −q₂: равнодействующая 0, центр принимается в середине, и пара сил теряется.
   При других разных знаках замена силой верна, но точка приложения может лежать вне участка,
   а текст всё равно пишет «центр тяжести трапеции».
3. «Что найти» хранится по имени (`R_E`); после добавления точки имена сдвигаются и отметка теряется
   или переходит на другую реакцию.
4. Проверочное уравнение не может показать «Ошибка»: решение с невязкой отсеивается раньше как «равновесие невозможно».
5. При α > 90° в записи проекций стоит острый угол (например, `cos 60°` вместо угла 120°); числа верные.
6. Не ошибка, а соглашение: у опорного стержня «+» направлен от опоры к конструкции, то есть «+» — сжатие.
7. «Убрать участок» не срабатывает никогда: `geomOK` проверяется, пока удаляемый узел ещё в списке узлов.
