# Статика — указания для Claude

Учебное приложение по механике (TS + Vite + React + Vitest): порт прототипа `prototype/statika.html`, выросший в набор
разделов по задачникам Мещерского (1975), Антонова («Прикладная механика») и Яблонского. Пользователь — студент,
общение — по-русски, кратко.

## Правила пользователя (обязательны)

- «Не меняй физику и правила знаков без согласования; любые расхождения с прототипом считай ошибкой, пока не доказано
  обратное. Если что-то в прототипе выглядит багом — сообщи, а не исправляй молча.»
- Расхождения с ответами задачников тоже не подгонять: сообщить пользователю и записать в README (раздел модуля,
  «Расхождения с книгой»).
- Промты для отдельных сессий — `docs/session-prompts.md`.
- Открытые вопросы к пользователю: K_D ≥ 1 в «Усталостной прочности» — подтвердить; пункт 8 дорожной карты
  (соединения) ждёт методики расчёта.

## Порядок работы

Дорожная карта — README, «Дорожная карта», и `src/app/roadmap.ts`; делать пункты по порядку. Пункты 11–13 сделаны:
11 — тело с неподвижной точкой и гироскоп (разделы `fixedpoint` и `gyro`; К.5, К.6, К.8 Яблонского сверены с
примерами в пункте 31), 12 — колебания систем (`vibration`), 13 — контакт тел в статике (в «Балках и рамах», см. README, «Контакт
тел»). Пункт 8 (соединения) — когда будет методика. Дальше — пробелы покрытия задачников
(`docs/coverage-meshchersky.md`, «Каких конструкторов не хватает»): пункты 14–31 сделаны (промты — `/mnt/project-files/prompts/`):
по Мещерскому собираются все задачи, кроме 9 вне формата, по Яблонскому — все 45 заданий. Дальше — новые книги
(`docs/coverage.md`, «Следующие книги»: нужны их PDF) и пункт 8. Пункты ведут параллельно по правилам ниже,
«Параллельные пункты».

Раздел устроен как `src/modules/<id>/`: `model/` (расчёт), `presets.ts` (готовые задачи с ответом книги `book` и
допуском `relTol`), `text/solution.ts` (текст решения, `Doc`), `draw/` (SVG), `ui/store.ts` (состояние, отмена, файл
проекта), `ui/<View>.tsx`, `index.tsx`. Образец — `src/modules/orbit/` или `varmass/`. Подключить: `src/app/registry.ts`,
`src/app/nav.ts` (вкладка в блоке), `src/app/roadmap.ts` (пункт `done` с `tab`). Название готовой задачи начинается
с источника: «Мещерский 50.22–50.23: …», «Яблонский, Д.13: … (пример)» — по нему работает «Задачник».

Проверки:
- по ходу — `npx tsc --noEmit -p .` и тесты своего раздела `npx vitest run tests/<id>.test.ts`; временные тесты
  `tests/tmp_*.test.ts` удалять;
- перед коммитом — `npx vitest run`, `npm run build`, `LANG=C.UTF-8 npm run e2e:files` (≈ 13 мин — запускать в фоне);
  `npm run compare:ui` (сверка с прототипом) — только если затронуты общий код (`src/shared`, `src/app`, `app.css`)
  или «Балки и рамы»;
- проверки в браузере для нового пункта — отдельным файлом `scripts/e2e/item-<номер>-<тема>.ts` (см.
  `scripts/e2e/README.md`); число разделов, готовых пунктов дорожной карты и бейдж «следующий» e2e берёт из `nav.ts`
  и `roadmap.ts` сам.
- Prettier: новые файлы — `npx prettier --write`; существующие — только если они уже отформатированы в HEAD.

Прежде чем начать: убедиться, что работа ещё не сделана — `src/app/roadmap.ts`, README, `docs/coverage*.md`,
`ls src/modules`, `git log --oneline origin/claude/exciting-gates-xx33r9`, `git branch -r` (ветки других сессий). Если
тема уже закрыта или идёт в другой ветке — не повторять, а сообщить пользователю.

После пункта: документация раздела — `docs/sections/<id>.md` (что решает, модель и формулы, правила знаков, готовые
задачи с ответами книги, расхождения с книгой, ограничения); в README — строка в списке разделов со ссылкой на этот
файл и число задач раздела в «Задачнике»; строки своих параграфов в `docs/coverage-meshchersky.md` и своих заданий в
`docs/coverage-yablonsky.md`; пункт в `src/app/roadmap.ts` (`status: 'done'`, `tab`) и его строка в README
(«Дорожная карта», ✅); коммит по-русски; push в ветку сессии. Общие итоги — `npm run totals` (см. ниже).

## Параллельные пункты: как сливать без конфликтов

Несколько пунктов ведутся одновременно, каждый в своей ветке от `claude/exciting-gates-xx33r9`, и их PR должны
вливаться в основу **в любом порядке без конфликтов**. Прошлые конфликты были только в общих строках, поэтому:

- **Не трогать общие итоги**: число задач и список заданий Яблонского в README («Задачник»), таблицы «Итог» в
  `docs/coverage-meshchersky.md` и `docs/coverage-yablonsky.md`, сводку в `docs/coverage.md`, текст после «Итога» и
  таблицу «Каких конструкторов не хватает». Их пересчитывает `npm run totals` (`tests/totals.test.ts`) и дописывает
  одна итоговая сессия после слияния всех пунктов.
- **Итоги пункта** — в новый файл `docs/items/item-<номер>.md`: что сделано, сколько задач Мещерского и Яблонского
  стало ✓ и ½ (по параграфам), расхождения с книгой, что осталось. Итоговая сессия переносит это в общие документы.
- **Только свои строки** в общих файлах: строки своих параграфов и заданий в таблицах покрытия, свой пункт в
  `roadmap.ts` и его строку в README, абзацы своих разделов в README. Каждый пункт получает свои разделы
  (`src/modules/<id>/`), у разных пунктов они не пересекаются.
- **Новые файлы вместо правки общих**: проверки в браузере — `scripts/e2e/item-<номер>-<тема>.ts`; тесты —
  `tests/<id>-<тема>.test.ts`; стили — свой `src/modules/<id>/<id>.css` с импортом из `index.tsx`, не в конец
  `app.css`; общий код — новым файлом в `src/shared/`, существующие файлы `src/shared` и `src/app` не менять без нужды.
- **Без новых разделов**: дополнять свои существующие разделы (новый раздел правит `registry.ts` и `nav.ts`, а это
  общие строки). Если без нового раздела никак — сообщить пользователю до начала.
- **Перед PR**: влить свежую основу (`git merge origin/claude/exciting-gates-xx33r9`), прогнать проверки и убедиться,
  что ветка сливается без конфликтов с ветками других пунктов этого этапа: `git merge-tree --write-tree HEAD
  origin/<их ветка>` (ветки — по открытым PR в основу или `git branch -r --sort=-committerdate | head`). Если
  конфликт есть — убрать его у себя, не трогая чужое.
- **Итоговая сессия** (после слияния всех пунктов): `npm run totals`, итоги пунктов из `docs/items/` — в
  `docs/coverage*.md` («закрыты пунктом N», «Каких конструкторов не хватает»), полный прогон проверок, публикация.

## Публикация — редко

Раз в 2–3 пункта или по просьбе пользователя. `npm run build && npm run bundle` → `dist/statika.html` (один файл,
проверен в браузере) и имена файлов сборки. Артефакт: `https://claude.ai/artifact/CmFedYKfiaWF36jqYQgj3y`
(версия 48, после пунктов 26–28: `assets/index-b5gevEuS.js`, `assets/index-DjnRZUfx.css`). Публиковать `dist/index.html` с `url` этого
артефакта и `files`: новые `assets/…` → `dist/assets/…`, старые имена → `null` (старые имена — `Artifact` `list`
`scope: "files"`). Затем отправить `dist/statika.html` пользователю.

## Экономия токенов

- Не запускать субагентов. Объединять команды в один вызов, читать файлы частями (`sed -n`, `grep`).
- Задачник читать по тексту; картинку страницы — только для спорного места и обрезанную. Скриншотов 2–3, не больше.
- Отчёт пользователю — короткий: что сделано, расхождения с книгой, план.

## Окружение

- Учебники — в папке `books/` ветки `main` (Мещерский 1975, Антонов, Яблонский — «Collection of tasks for term
  papers on theoretical mechanics.pdf»). В рабочую ветку их не коммитить; достать во временную папку:
  `git fetch origin main && git archive origin/main books | tar -x -C <scratchpad>`. Текст страницы: PyMuPDF
  (`python3 -I`), рендер `page.get_pixmap(dpi=120)`; номер страницы PDF у Мещерского совпадает с печатным.
- Playwright: Chromium в `/opt/pw-browsers` (см. `chromiumPath()` в `scripts/e2e-files.ts`); шрифты Google
  блокировать (`page.route(/fonts\.g/, r => r.abort())`).
- Не запускать `pkill -f "vite preview…"` в команде, содержащей этот же текст: команда убьёт собственную оболочку.
